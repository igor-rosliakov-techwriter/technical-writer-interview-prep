# Documentation English: 35 Useful Expressions

A starter phrasebook for reading documentation, writing instructions, and explaining technical workflows in interviews. Learn each expression together with its object and preposition. The examples are short, illustrative sentences written for this guide.

Небольшая памятка для чтения документации, написания инструкций и ответов на интервью. Запоминай выражение целиком: с дополнением и предлогом. В каждой строке есть пример и его перевод; примеры составлены для этой памятки.

## 1. Files, Data, and Changes / Файлы, данные и изменения

| English expression | Русский смысл | Example / Пример | Usage / Подсказка |
| --- | --- | --- | --- |
| **1. store data in …** | хранить данные в … | The application stores settings in a file.<br>Приложение хранит настройки в файле. | `store` описывает хранение: `in a file`, `in a database`. Для платформы: `on GitHub`. |
| **2. save changes to …** | сохранить изменения в … | Save your changes to the configuration file.<br>Сохраните изменения в файле конфигурации. | `save` здесь означает действие сохранения. Сравни: `save the file` — сохранить файл; `store files` — хранить файлы. |
| **3. retrieve data from …** | получить, извлечь данные из … | The client retrieves data from the server.<br>Клиент получает данные с сервера. | `from` указывает источник. Часто речь об уже существующих данных. Более простое `get data from` тоже возможно. |
| **4. update a file** | обновить файл | Update the configuration file with the new settings.<br>Обновите файл конфигурации, добавив новые настройки. | `update` — изменить содержимое до нужного состояния. Это не обязательно скачать новую версию файла. |
| **5. keep documentation up to date** | поддерживать документацию в актуальном состоянии | We update the examples to keep the documentation up to date.<br>Мы обновляем примеры, чтобы документация оставалась актуальной. | Шаблон: `keep + object + state`. Здесь `up to date` без дефисов; перед существительным: `up-to-date documentation`. |
| **6. track changes to …** | отслеживать изменения в … | Git tracks changes to files in a repository.<br>Git отслеживает изменения файлов в репозитории. | `changes to a file` — изменения файла. `track` подходит для истории изменений; `monitor` часто используют для наблюдения за текущим состоянием системы. |
| **7. push changes to …** | отправить изменения в … | Push your changes to the remote repository.<br>Отправьте изменения в удалённый репозиторий. | В Git отправляются коммиты. `push changes to GitHub` — направление; `the repository is on GitHub` — расположение. Название `GitHub` обычно без `the`. |

## 2. Commands and Configuration / Команды и настройка

| English expression | Русский смысл | Example / Пример | Usage / Подсказка |
| --- | --- | --- | --- |
| **8. run a command** | выполнить, запустить команду | Run the command in a terminal.<br>Выполните команду в терминале. | Обычно `run` или `execute`, а не `make a command`. Для инструкции достаточно `Run …`; для рассказа о себе — `I run …`. |
| **9. install dependencies** | установить зависимости | Install the dependencies before you build the project.<br>Установите зависимости перед сборкой проекта. | `dependencies` — пакеты или компоненты, необходимые проекту. `the dependencies` — конкретные зависимости этого проекта. |
| **10. configure a service** | настроить сервис | Configure the service to use HTTPS.<br>Настройте сервис на использование HTTPS. | Шаблон: `configure + object + to + verb`. `configure the server`, но `configure the settings` тоже грамматически возможно. |
| **11. set … to …** | задать чему-либо значение … | Set the timeout to 30 seconds.<br>Установите время ожидания равным 30 секундам. | `set + parameter + to + value`. Например, `set the value to 10`, а не `set the value as 10`. |
| **12. specify a path to …** | указать путь к … | Specify the path to the configuration file.<br>Укажите путь к файлу конфигурации. | `specify` — явно указать нужное значение. Путь **к** файлу: `path to the file`; источник данных: `data from the file`. |
| **13. replace … with …** | заменить … на … | Replace the placeholder with your project ID.<br>Замените заполнитель идентификатором своего проекта. | Сначала то, что заменяем, затем новое: `replace OLD with NEW`. `placeholder` — обозначение, вместо которого нужно подставить своё значение. |
| **14. apply changes** | применить изменения | Restart the service to apply the changes.<br>Перезапустите сервис, чтобы применить изменения. | `save` сохраняет правки, `apply` вводит их в действие. Перезапуск нужен в этом примере; в реальной инструкции проверь требования продукта. |

## 3. Capabilities and API Behavior / Возможности и поведение API

| English expression | Русский смысл | Example / Пример | Usage / Подсказка |
| --- | --- | --- | --- |
| **15. provide someone with something** | предоставить кому-либо что-либо; обеспечить чем-либо | The guide provides you with examples.<br>Руководство содержит примеры для вас. | `provide + recipient + with + thing`: `provides users with examples`. Без получателя: `The guide provides examples.` Пишется `provide`, а не `porvide`. |
| **16. allow someone to do something** | позволять кому-либо что-либо делать | This permission allows users to edit files.<br>Это разрешение позволяет пользователям редактировать файлы. | `allow + someone + to + verb`: `allows users to edit`. Когда просто описываешь возможность, часто короче `Users can edit files.` |
| **17. require someone to do something** | требовать от кого-либо выполнения действия | The service requires users to sign in.<br>Сервис требует, чтобы пользователи вошли в систему. | `require + someone + to + verb`. С предметом: `The service requires authentication.` — Сервис требует аутентификации. |
| **18. send a request to …** | отправить запрос к … | Send a GET request to the endpoint.<br>Отправьте GET-запрос к этой конечной точке API. | `to` — адресат. `send a request to the server` тоже естественно. `endpoint` — конечная точка API, не весь API целиком. |
| **19. return a response** | вернуть ответ | The server returns a response containing the user ID.<br>Сервер возвращает ответ, содержащий идентификатор пользователя. | `return` часто описывает результат: `return a value`, `return an error`. У HTTP-ответа также есть код состояния и заголовки. |
| **20. include … in …** | включить, добавить … в … | Include the record ID in the URL.<br>Включите идентификатор записи в URL. | `include + what + in + where`: `include the token in the header`. Конкретное место зависит от API. |
| **21. interact with …** | взаимодействовать с … | Clients interact with the service through an API.<br>Клиенты взаимодействуют с сервисом через API. | `interact with` — с чем; `through an API` — через что. В инструкции по возможности называй конкретное действие: получить, создать или обновить. |

## 4. Review, Checks, and Automation / Ревью, проверки и автоматизация

| English expression | Русский смысл | Example / Пример | Usage / Подсказка |
| --- | --- | --- | --- |
| **22. review changes** | просмотреть и оценить изменения; провести ревью | Review the changes before publishing the guide.<br>Проверьте изменения перед публикацией руководства. | `review` подразумевает содержательную оценку: например, точности и ясности. `review the documentation` — проверить документацию. |
| **23. check for errors** | проверить, нет ли ошибок | Check the examples for errors.<br>Проверьте примеры на наличие ошибок. | `check + object + for + problem`. Сравни: `check the file` — проверить файл; `check for errors` — поискать ошибки. |
| **24. verify that …** | убедиться, что …; проверить, что … | Verify that the link opens the correct page.<br>Убедитесь, что ссылка открывает нужную страницу. | После `that` идёт утверждение: `verify that + subject + verb`. Проверка должна дать основание считать его верным. |
| **25. validate … against …** | проверить соответствие … заданным правилам или схеме | Validate the JSON response against the schema.<br>Проверьте соответствие JSON-ответа схеме. | `against` вводит критерий проверки. `check`, `verify` и `validate` частично пересекаются; `validate` особенно полезно при явных правилах. |
| **26. run tests** | запускать, выполнять тесты | Run the tests before merging the changes.<br>Запустите тесты перед слиянием изменений. | `run tests`, `run checks`, `run a build` — выполнять тесты, проверки, сборку. Запуск ещё не означает успешное прохождение. |
| **27. trigger a pipeline** | вызвать запуск pipeline | A push to the main branch triggers the pipeline.<br>Отправка изменений в основную ветку запускает pipeline. | `trigger` подчёркивает причину запуска; это может быть событие или ручное действие. В примере речь о pipeline, настроенном на push. |
| **28. pass a check** | успешно пройти проверку | All checks have passed.<br>Все проверки успешно пройдены. | Время меняет смысл: `All checks pass.` — Все проверки проходят; `All checks have passed.` — Все проверки прошли. `The check failed.` — Проверка завершилась неудачно. |

## 5. Purpose, Sequence, and Conditions / Цель, порядок и условия

| English expression | Русский смысл | Example / Пример | Usage / Подсказка |
| --- | --- | --- | --- |
| **29. to + verb** | чтобы …; для того чтобы … | To publish the guide, select **Publish**.<br>Чтобы опубликовать руководство, выберите **Publish**. | Для цели: `to publish`, а не `for publish`. `for publishing` возможно в другом шаблоне, например `a tool for publishing docs`. |
| **30. before + verb-ing** | перед тем как …; перед … | Review the draft before publishing it.<br>Проверьте черновик перед его публикацией. | После `before` здесь форма `-ing`: `before publishing`, не `before publish`. Полный вариант: `before you publish it`. |
| **31. after + verb-ing** | после того как …; после … | After updating the file, save your changes.<br>После обновления файла сохраните изменения. | В этом шаблоне обе операции выполняет один человек. Если действующие лица разные, назови их: `After the build finishes, review the output.` |
| **32. if you haven't … yet** | если вы ещё не … | If you haven't configured the service yet, configure it now.<br>Если вы ещё не настроили сервис, настройте его сейчас. | После `haven't` нужна третья форма глагола: `configured`, `run`, `written`. Полное `have not` тоже подходит. Активная форма естественна в инструкции. |
| **33. once …** | как только …; после того как … | Once the build finishes, review the output.<br>Когда сборка завершится, проверьте результат её работы. | В таком условии о будущем: `once the build finishes`, обычно без `will`. Здесь `once` обозначает завершение этапа, а не «один раз». |
| **34. by default** | по умолчанию | By default, the tool stores logs locally.<br>По умолчанию инструмент хранит логи локально. | То, что происходит без изменения настройки. Оборот `by default`, не `on default`. Поведение в примере условное. |
| **35. depend on …** | зависеть от … | The output format depends on the configuration.<br>Формат результата зависит от конфигурации. | Предлог `on`, не `from`. Единственное число: `The result depends on …`; множественное: `The results depend on …`. |

## Practice / Как повторять

Read seven rows at a time. Cover the English column, translate the Russian meanings, then make one sentence about your own work for each expression. Keep the preposition when you change the object.

Учи по семь строк. Закрой английскую колонку, восстанови выражения по русскому смыслу и составь с каждым одно предложение про свою работу. Меняя дополнение, сохраняй нужный предлог: `store settings in a file` → `store records in a database`.

## Language References / Языковые источники

These references support the grammar and style notes. The selection is a practical starter set, not a measured frequency ranking.

Источники подтверждают грамматику и отдельные рекомендации по стилю. Подборка рассчитана на практику; это не статистический рейтинг частотности.

- [Cambridge: the pattern with **provide**](https://dictionary.cambridge.org/us/grammar/british-grammar/word-patterns-provide). Confirms the `provide someone with something` pattern. Подтверждает конструкцию с `with`.
- [Google developer documentation style guide: procedures](https://developers.google.com/style/procedures). Guidance on direct instructions, purpose, and action order. Рекомендации по форме инструкции, выражению цели и порядку действий.
- [Microsoft Writing Style Guide: **allow, allows**](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/a/allow-allows). A style preference for direct descriptions of capabilities; `allow someone to do something` remains a valid grammatical pattern. Это рекомендация по стилю описания возможностей; сама конструкция с `allow` грамматически корректна.
